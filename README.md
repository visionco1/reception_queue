# نظام استقبال العملاء وإدارة الطابور

نظام ويب مبني بـ **Laravel 13** يعمل بالكامل من المتصفح على الآيباد والكمبيوتر والجوال وشاشة التلفزيون، وينفذ نطاق النسخة الأولى (MVP) كما في وثيقة المتطلبات:

| الجزء | الرابط | من يستخدمه |
|---|---|---|
| آيباد الاستقبال | `/kiosk/{رمز سري}` | العميل الحضوري (بدون تسجيل دخول) |
| شاشة الانتظار | `/display/{رمز سري}` | تلفزيون الصالة |
| لوحة الموظف | `/staff` | الموظفون (تسجيل دخول) |
| لوحة الإدارة | `/admin` | المشرف ومدير النظام |

---

## ما تم تنفيذه

**آيباد الاستقبال:** الاسم، رقم الجوال، بائع/مشتري، البنك، ثم زر «تسجيل وأخذ رقم». يظهر رقم الانتظار (مثل `M023` أو `B014`) وعدد العملاء قبله، ويُرسل الرقم على واتساب، ثم تعود الشاشة فارغة تلقائيًا حفاظًا على خصوصية العميل التالي. يقبل الأرقام العربية (٠٥…) والصيغ الدولية، ولا يصدر رقمين لنفس العميل في نفس اليوم.

**الطابور المشترك:** قائمة انتظار واحدة يراها كل الموظفين وتتحدث تلقائيًا كل ثانيتين ونصف. أي موظف متاح يأخذ أي عميل، و**القفل اللحظي** يضمن أن موظفًا واحدًا فقط يحصل عليه (تحديث شرطي ذري في قاعدة البيانات داخل Transaction — مُختبَر بستة طلبات متزامنة فعلية). الموظف يخدم عميلًا واحدًا في كل مرة.

**العميل الحالي:** إعادة النداء، حضر العميل (بدء الخدمة)، إنهاء الخدمة مع ملاحظة اختيارية، لم يحضر (تخطي)، إرجاع للطابور، وزر «استدعاء التالي» للأقدم انتظارًا.

**شاشة الانتظار:** الرقم الحالي بحجم كبير جدًا، «توجّه إلى مكتب X» على شكل ختم، آخر الأرقام المستدعاة، صوت تنبيه، حركة بسيطة عند تغيّر الرقم، الشعار والرسالة التعريفية، وعدد المنتظرين. تعيد تحميل نفسها تلقائيًا عند تغيير إعداداتها. نطق الرقم صوتيًا متاح كخيار.

**العملاء عن بعد:** يبدأ الموظف برقم الجوال؛ إن كان مسجلًا يظهر تنبيه بسجله ويُضاف تفاعل جديد لنفس السجل بدل التكرار. لا رقم انتظار ولا رسائل طابور، ويُنسب التفاعل للموظف مع مصدر العميل (واتساب / اتصال / إحالة / الموقع / غيره).

**وكلاء البنوك:** لكل بنك قائمة وكلاء (مناديب) يديرها مدير النظام. على الآيباد، بعد اختيار البنك تظهر قائمة وكلائه ويختار العميل وكيله (أو «لا أعرف / بدون وكيل»). الوكيل الواحد يتابع أكثر من بائع ومشتري.

**ربط البائع بالمشتري (الصفقة):** من مربع «عميلي الحالي» يضغط الموظف «ربط بالطرف الآخر» فتظهر عملاء اليوم، والمقترح أولًا من له نفس الوكيل والنوع المقابل. إذا كان الطرف الآخر ينتظر يُستدعى فورًا لنفس المكتب ويظهر الرقمان معًا على الشاشة. وإذا أخذ أي موظف لاحقًا أحد طرفي صفقة مربوطة يُستدعى الطرف الآخر معه تلقائيًا. «إنهاء الخدمة» ينهي الطرفين معًا، و«لم يحضر» و«إرجاع للطابور» لكل طرف على حدة، ويمكن فك الربط عند الخطأ.

**أنواع عملاء أخرى (عن بُعد):** العميل عن بعد قد لا يكون بائعًا ولا مشتريًا؛ يختار الموظف «أخرى» ثم النوع من قائمة يديرها مدير النظام (استشارة قانونية، مستثمر...). الآيباد يبقى للبائع والمشتري فقط.

**قاعدة بيانات موحدة:** جدول للعملاء (رقم الجوال فريد) منفصل عن جدول الزيارات والتفاعلات، والبحث برقم الجوال أو الاسم.

**واتساب:** رسالة بعد التسجيل، رسالة اختيارية عند اقتراب الدور، رسالة عند الاستدعاء برقم المكتب، ورسالة شكر مع سطر اختياري للتعريف بالخدمات. النصوص قابلة للتعديل من لوحة الإدارة، وكل رسالة تُحفظ بحالتها ووقتها (بانتظار الإرسال، أُرسلت، وصلت، قُرئت، فشلت)، وتُعاد تلقائيًا عند الفشل دون تعطيل الاستقبال، ويمكن إعادة إرسالها يدويًا.

**التسجيل التلقائي:** وقت التسجيل، نوع التسجيل، رقم الانتظار، وقت الاستدعاء، المكتب، الموظف، بدء وإنهاء الخدمة، مدة الانتظار، مدة الخدمة، المصدر، وحالة الرسائل. كل تغيير حالة يُسجل مع الوقت والموظف، وسجل تدقيق لكل حدث مهم (من أخذ العميل، من عدّل البيانات، الدخول، التصدير، تعديل الإعدادات).

**لوحة الإدارة:** نظرة اليوم المباشرة، التقارير، كل الزيارات بمرشحات، قاعدة العملاء، سجل رسائل واتساب، الموظفون والصلاحيات، المكاتب، البنوك، نصوص واتساب، الإعدادات (الشعار، ألوان شاشة العرض، ترميز الأرقام، روابط الأجهزة)، وسجل التدقيق. التصدير إلى **Excel (xlsx)** و**CSV** يدعم العربية.

**التقارير:** عدد العملاء يوميًا/أسبوعيًا/شهريًا، نوع العميل (مشتري/بائع/أنواع أخرى)، تقرير حسب وكيل البنك (بائعون، مشترون، صفقات مربوطة)، الحضوري مقابل عن بعد، أكثر البنوك ورودًا، متوسط مدة الانتظار والخدمة، عدد من خدمهم كل موظف، أوقات الذروة، والعملاء المتكررون.

## التقنية المستخدمة

- **الخادم:** PHP 8.3 أو أحدث، Laravel 13.
- **قاعدة البيانات:** MySQL 8 أو MariaDB 10.6+ للإنتاج (SQLite مدعومة للتجربة).
- **الواجهة:** Blade + Alpine.js + Tailwind CSS، مع خطوط عربية مضمّنة محليًا (IBM Plex Sans Arabic و Noto Kufi Arabic) فلا يعتمد على خدمات خارجية.
- **التحديث اللحظي:** استعلام دوري خفيف (كل 2.5 ثانية) يعمل على أي استضافة دون خادم WebSockets.
- **واتساب:** WhatsApp Business Platform (Cloud API) من Meta مباشرة، مع وضع تجربة يسجل الرسائل دون إرسالها.
- **المهام الخلفية:** طابور Laravel لإرسال الرسائل، ومجدول للنسخ الاحتياطي اليومي وإغلاق تذاكر الأيام السابقة.

## التشغيل السريع للتجربة (على جهاز المطور)

الملف المسلَّم يحتوي على مجلد `vendor` والواجهة المبنية مسبقًا، فيكفي PHP 8.3:

```bash
cp .env.example .env
php artisan key:generate
touch database/database.sqlite
php artisan migrate --seed                      # المكاتب والبنوك وحساب المدير وروابط الأجهزة
php artisan db:seed --class=DemoSeeder         # اختياري: موظفون وبيانات 30 يومًا للتجربة
php artisan serve
```

ثم في نافذة أخرى: `php artisan queue:work` لإرسال رسائل واتساب.

يطبع أمر `migrate --seed` رابط الآيباد ورابط شاشة العرض. الدخول للوحة: `http://localhost:8000/login` باسم المستخدم `admin` وكلمة المرور `ChangeMe@2026` (أو ما تضعه في `ADMIN_PASSWORD` قبل التشغيل). بيانات التجربة تضيف موظفين (`salman`، `areej`، `faisal`، `mona`) ومشرفة (`supervisor`) بكلمة المرور `password`.

لإعادة بناء التبعيات من المصدر: `composer install` و `npm install && npm run build`.

## النشر على خادم سحابي مملوك للشركة

المقترح: خادم Ubuntu 24.04 بسيط (2 vCPU و 2–4 جيجابايت ذاكرة تكفي بسهولة)، Nginx، PHP-FPM 8.3، MySQL 8، وشهادة HTTPS مجانية من Let's Encrypt.

```bash
# 1) الحزم
sudo apt install nginx mysql-server php8.3-fpm php8.3-{mysql,mbstring,xml,zip,curl,intl,gd,bcmath} supervisor unzip

# 2) قاعدة البيانات
sudo mysql -e "CREATE DATABASE reception CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'reception'@'localhost' IDENTIFIED BY 'كلمة-مرور-قوية';
GRANT ALL ON reception.* TO 'reception'@'localhost';"

# 3) التطبيق في /var/www/reception
cp .env.example .env    # ثم عدّل القيم أدناه
php artisan key:generate
php artisan migrate --force --seed
php artisan config:cache && php artisan route:cache && php artisan view:cache
sudo chown -R www-data:www-data storage bootstrap/cache public/uploads
```

القيم الأساسية في `.env`:

```dotenv
APP_ENV=production
APP_DEBUG=false
APP_URL=https://reception.example.com
APP_TIMEZONE=Asia/Riyadh

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_DATABASE=reception
DB_USERNAME=reception
DB_PASSWORD=...

ADMIN_PASSWORD=كلمة-مرور-أولية-قوية
QUEUE_CONNECTION=database
```

**Nginx:** وجّه جذر الموقع إلى مجلد `public` (الإعداد القياسي لـ Laravel) وفعّل HTTPS عبر `certbot --nginx`.

**المجدول (cron)** — سطر واحد لمستخدم www-data:

```
* * * * * cd /var/www/reception && php artisan schedule:run >> /dev/null 2>&1
```

**عامل الطابور (Supervisor)** — ملف `/etc/supervisor/conf.d/reception-worker.conf`:

```ini
[program:reception-worker]
command=php /var/www/reception/artisan queue:work --sleep=1 --tries=1 --max-time=3600
user=www-data
autostart=true
autorestart=true
stdout_logfile=/var/www/reception/storage/logs/worker.log
```

ثم `sudo supervisorctl reread && sudo supervisorctl update`.

> **استضافة مشتركة (cPanel) بدون Supervisor:** ضع `QMS_QUEUE_VIA_SCHEDULER=true` في `.env` وسيُشغَّل عامل الطابور من المجدول كل دقيقة. أي رسالة تبقى عالقة تُعاد جدولتها تلقائيًا كل 10 دقائق.

**إذا كان الخادم خلف Cloudflare أو موازن أحمال** فعّل سطر `trustProxies` في `bootstrap/app.php`.

## الرفع على Hostinger (استضافة مشتركة)

جُرّبت هذه الطريقة على نفس ترتيب ملفات Hostinger وبنفس قيودها: المشروع كاملًا داخل `public_html`، وملف `.htaccess` الموجود في جذر المشروع يحوّل كل الطلبات إلى مجلد `public` فلا يمكن فتح `.env` أو أي ملف من ملفات المشروع من المتصفح.

> **قيد مهم في Hostinger:** دالة `proc_open` معطّلة، فلا يستطيع PHP تشغيل برامج أخرى. لذلك: يُشغَّل `composer install` مع `--no-scripts`، والمهام الدورية في النظام تعمل داخل نفس عملية PHP، والنسخ الاحتياطي يعمل بلغة PHP بدل `mysqldump`. كل هذا مضبوط في الكود، فقط اتبع الأوامر كما هي.

1. **إصدار PHP:** من hPanel ← **PHP Configuration** اختر **8.3** أو أحدث.
2. **قاعدة البيانات:** من **Databases** أنشئ قاعدة MySQL ومستخدمًا، واحفظ الاسم واليوزر وكلمة المرور (تبدأ بـ `u123456789_`).
3. **SSH:** من **Advanced ← SSH Access** فعّل الخدمة، ثم اتصل: `ssh -p 65002 u123456789@IP`.
4. **تنزيل المشروع من GitHub:**
   ```bash
   cd ~/domains/your-domain.com
   mv public_html public_html_old          # احتياط لمحتوى المجلد الحالي، احذفه بعد التأكد
   git clone https://github.com/USER/REPO.git public_html
   cd public_html
   composer install --no-dev --optimize-autoloader --no-scripts
   php artisan package:discover --ansi
   ```
   مجلد `public/build` (ملفات التصميم والخطوط المبنية) محفوظ داخل المستودع لأن الاستضافة لا تحتوي Node.js. بعد أي تعديل في `resources/css` أو `resources/js` شغّل `npm run build` على جهازك قبل `git push`.
5. **ملف الإعدادات:**
   ```bash
   cp .env.hostinger.example .env
   nano .env
   ```
   عدّل الأسطر المعلّمة بـ ←: `APP_URL` وبيانات قاعدة البيانات و`ADMIN_PASSWORD`. للحفظ في nano: `Ctrl+O` ثم `Enter` ثم `Ctrl+X`. (أو عدّله من File Manager.)
6. **التثبيت:**
   ```bash
   php artisan key:generate --force
   php artisan migrate --force --seed
   php artisan optimize
   ```
   يطبع أمر `migrate` رابط الآيباد ورابط شاشة العرض وحساب المدير.
7. **المهام الدورية وإرسال واتساب:** اعرف مسار PHP بالأمر `which php`، ثم من **Advanced ← Cron Jobs** أنشئ مهمة من نوع **Custom** تعمل **كل دقيقة** (`* * * * *`):
   ```
   /usr/bin/php /home/u123456789/domains/your-domain.com/public_html/artisan schedule:run
   ```
   استبدل مسار PHP ورقم المستخدم والدومين. هذا السطر وحده يرسل رسائل واتساب خلال ثوانٍ (لأن `QMS_QUEUE_VIA_SCHEDULER=true`) ويشغّل النسخ الاحتياطي اليومي وإغلاق تذاكر الأيام السابقة. توقيت Cron في Hostinger هو UTC ولا يؤثر لأن المهمة تعمل كل دقيقة والنظام يستخدم `APP_TIMEZONE`.
8. **SSL:** تأكد من تفعيل شهادة SSL المجانية للدومين، ثم افتح `https://your-domain.com/login`.

**التحديثات لاحقًا:** ارفع التعديلات إلى GitHub من جهازك، ثم على السيرفر:
```bash
cd ~/domains/your-domain.com/public_html && bash deploy.sh
```
السكربت يسحب التعديلات ويثبت الحزم ويحدّث قاعدة البيانات دون أن يلمس `.env` أو `storage`. وإذا عدّلت `.env` يدويًا نفّذ بعدها `php artisan optimize`.

**بدون Git:** ارفع `reception-queue-laravel.zip` من File Manager إلى `public_html` واستخرجه، وانقل **محتوى** مجلد `reception-queue` إلى `public_html` مباشرة (الملف يحتوي `vendor` و`public/build` جاهزين فلا حاجة لـ composer)، ثم أكمل من الخطوة 5. ويمكن تنفيذ أوامر الخطوة 6 بدون SSH بإنشاء مهمة Cron مؤقتة لكل أمر ثم حذفها.

**النسخ الاحتياطية:** تُحفظ يوميًا في `storage/app/backups` بصيغة `.sql.gz`، وتُستعاد من phpMyAdmin ← Import.

## ربط واتساب (WhatsApp Business Platform من Meta)

1. أنشئ تطبيقًا في [Meta for Developers](https://developers.facebook.com/) وأضف منتج WhatsApp، واربط رقم هاتف الشركة بحساب WhatsApp Business.
2. أنشئ **رمز وصول دائم** (System User Token) بصلاحية `whatsapp_business_messaging`.
3. ضع في `.env`:

   ```dotenv
   WHATSAPP_DRIVER=meta
   WHATSAPP_PHONE_NUMBER_ID=...      # من صفحة WhatsApp > API Setup
   WHATSAPP_ACCESS_TOKEN=...
   WHATSAPP_APP_SECRET=...           # من إعدادات التطبيق الأساسية (للتحقق من Webhook)
   WHATSAPP_WEBHOOK_VERIFY_TOKEN=أي-نص-سري-تختاره
   ```

   ثم `php artisan config:cache`.
4. **القوالب:** الرسائل التي يبدأها النشاط التجاري (وهي كل رسائل الطابور لأن العميل لم يراسل الشركة) تتطلب **قوالب معتمدة** من Meta. أنشئ في WhatsApp Manager أربعة قوالب من فئة Utility باللغة العربية، مثل:

   | الرسالة | اسم مقترح للقالب | نص القالب | ترتيب المتغيرات في لوحة الإدارة |
   |---|---|---|---|
   | بعد التسجيل | `queue_registered` | مرحبًا {{1}}، تم تسجيلك بنجاح. رقم انتظارك: {{2}}. | `name,ticket` |
   | اقتراب الدور | `queue_near_turn` | متبقي قبلك عميل واحد. رقمك {{1}}. | `ticket` |
   | الاستدعاء | `queue_called` | حان دورك الآن. رقمك {{1}} - يرجى التوجه إلى مكتب {{2}}. | `ticket,desk` |
   | الشكر | `queue_thanks` | شكرًا لزيارتكم. سعدنا بخدمتكم ونسعد دائمًا بتعاملكم معنا. | (فارغ) |

   بعد اعتمادها اكتب اسم كل قالب وترتيب متغيراته في **الإدارة ← رسائل واتساب**. اترك اسم القالب فارغًا لإرسال النص كما هو (يعمل فقط داخل نافذة 24 ساعة من آخر رسالة من العميل، ومفيد للتجربة).
5. **حالات التسليم:** في إعدادات Webhook للتطبيق ضع الرابط `https://النطاق/webhooks/whatsapp` ونفس `WHATSAPP_WEBHOOK_VERIFY_TOKEN`، واشترك في حقل `messages`. بعدها تظهر حالتا «وصلت» و«قُرئت» في سجل الرسائل.
6. جرّب من **الإدارة ← رسائل واتساب ← إرسال رسالة تجريبية**.

**التكلفة التشغيلية:** تحتسب Meta رسومًا لكل رسالة قالب حسب فئته (رسائل الطابور من فئة Utility) والدولة، وتتغير الأسعار دوريًا؛ راجع صفحة أسعار WhatsApp Business Platform الرسمية قبل الإطلاق. يمكن تقليل التكلفة بإيقاف رسالة «اقتراب الدور» أو رسالة الشكر من لوحة الإدارة.

## تجهيز الأجهزة

**آيباد الاستقبال**
1. من **الإدارة ← الإعدادات والأجهزة** انسخ رابط آيباد الاستقبال وافتحه في Safari.
2. «مشاركة» ← «إضافة إلى الشاشة الرئيسية» ليفتح بملء الشاشة دون شريط العنوان.
3. فعّل **الوصول الموجّه** (الإعدادات ← تسهيلات الاستخدام ← الوصول الموجّه) واضغط زر التشغيل الجانبي ثلاث مرات داخل الصفحة لقفل الآيباد عليها.
4. الصفحة تعود فارغة تلقائيًا بعد عرض الرقم، وتمسح أي نموذج متروك نصف ممتلئ بعد دقيقتين، وتُحدِّث نفسها كل نصف ساعة لتظهر تعديلات الإدارة.

**شاشة الانتظار (تلفزيون)**
1. افتح رابط شاشة العرض في متصفح التلفزيون أو جهاز صغير متصل به (Chromecast مع متصفح، Fire TV، أو كمبيوتر صغير) بوضع ملء الشاشة.
2. المس الشاشة أو اضغط زر الريموت مرة واحدة لتفعيل صوت التنبيه (قيود المتصفحات). على جهاز كمبيوتر يمكن تشغيل Chrome بوضع الكشك دون الحاجة لذلك:
   `chrome --kiosk --autoplay-policy=no-user-gesture-required "رابط-شاشة-العرض"`

**الروابط سرية:** من يملك الرابط يفتح الشاشة. إن تسرب رابط أنشئ رابطًا جديدًا من نفس الصفحة فيتوقف القديم فورًا.

## الصلاحيات

| الدور | الصلاحيات |
|---|---|
| موظف | الطابور، أخذ العملاء، إضافة العملاء عن بعد، البحث في العملاء (كل العملاء أو من خدمهم فقط حسب الإعداد)، عملائي اليوم |
| مشرف | كل ما سبق + نظرة اليوم، التقارير، كل الزيارات، قاعدة العملاء، التصدير، سجل رسائل واتساب |
| مدير النظام | كل ما سبق + الموظفون والصلاحيات، المكاتب، البنوك ووكلاؤها، أنواع العملاء، نصوص واتساب، الإعدادات وروابط الأجهزة، سجل التدقيق |

تعطيل حساب موظف ينهي جلسته فورًا. لا يستطيع المدير تعطيل حسابه أو إزالة صلاحية المدير عن نفسه.

## دليل التشغيل المختصر

**الموظف — بداية الدوام:** سجّل الدخول، وتأكد من رقم مكتبك أعلى الصفحة (يظهر للعميل على الشاشة).

**ربط البائع بالمشتري:** أثناء خدمة أحد الطرفين اضغط «ربط بالطرف الآخر» واختر الطرف (المقترح عليه علامة «مقترح: نفس الوكيل»). إن كان ينتظر يُستدعى لمكتبك فورًا، ثم «إنهاء الخدمة للطرفين».

**خدمة عميل حضوري:**
1. اضغط «أخذ العميل» بجانب أي عميل في القائمة، أو «استدعاء التالي» لأقدم المنتظرين.
2. يظهر رقمه ورقم مكتبك على شاشة الصالة ويصله واتساب.
3. عند وصوله اضغط «حضر العميل — بدء الخدمة» (اختياري)، ولم يصل؟ «إعادة النداء»، أو «لم يحضر — تخطي».
4. في النهاية «إنهاء الخدمة» مع ملاحظة إن أردت؛ تُحسب المدة وتصله رسالة الشكر.
5. «إرجاع للطابور» يعيده للقائمة ليأخذه موظف آخر.

**عميل عن بعد (اتصال، واتساب، إحالة…):** «إضافة عميل عن بُعد» ← اكتب رقم الجوال واضغط «تحقق» ← إن ظهر أنه مسجل مسبقًا فسيُضاف التفاعل لسجله ← أكمل النوع والمصدر والبنك ← «حفظ التفاعل».

**البحث عن عميل:** اكتب رقم الجوال (أو جزءًا منه) في خانة البحث، ومن سجل العميل يمكن تعديل بياناته الأساسية وتسجيل تفاعل جديد.

**الإدارة اليومية:** «نظرة اليوم» تعرض المنتظرين الآن، ومن يخدم من، وآخر النداءات، وتنبه إن فشل إرسال رسائل. التقارير والتصدير من القائمة الجانبية.

## النسخ الاحتياطي والاستعادة

- نسخة يومية تلقائية الساعة 2:30 صباحًا في `storage/app/backups` (مضغوطة)، ويُحتفظ بآخر 14 نسخة (`QMS_BACKUP_KEEP`).
- يدويًا: `php artisan qms:backup`.
- يُنصح بنسخ هذا المجلد خارج الخادم أيضًا (مثل لقطات القرص التلقائية لدى مزود السحابة أو rsync إلى تخزين خارجي).
- الاستعادة في MySQL: `gunzip -c backup_....sql.gz | mysql -u reception -p reception`.
